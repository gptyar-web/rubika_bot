# Rubika Control Pro — پنل فارسی مدیریت روبیکا

## پنل مستقل با مخزن رمزگذاری‌شدهٔ توکن

فایل‌های بستهٔ آماده در پوشهٔ [`control-pro`](control-pro/README.md) قرار دارند. [بازکردن پنل جدید](https://mozdbaranarshiya.github.io/rubika_bot/control-pro/) · [جدول ۱۵۰ قابلیت](control-pro/docs/FEATURES.md).

در این نسخه، توکن پس از یک بار ثبت با AES-GCM در مرورگر ذخیره می‌شود و برای ورود بعدی فقط رمز مخزن لازم است. این پنل مستقل از سرویس و نسخهٔ فعلی ریشه است؛ تنظیمات و داده‌های آن‌ها خودکار با هم ادغام نمی‌شوند.

پنل واکنش‌گرا با **HTML، CSS و JavaScript**؛ بدون Python، بدون مرحله Build، مناسب انتشار در **GitHub Pages**. فونت محلی Vazirmatn، ظاهر روشن و تاریک، آیکون اختصاصی، صفحات مدیریتی و نصب PWA دارد.

## نسخه ۳٫۱ — موتور JavaScript

نسخه جدید علاوه بر رابط GitHub Pages این اجزا را دارد:

- موتور پردازش `NewMessage` با تأیید مستقل مدیریت و پاسخگویی برای هر مقصد؛ تنظیمات قدیمی به‌طور خودکار اجرای پیام را فعال نمی‌کنند.
- حذف محتوای مستند، لینک و دامنه مجاز، کلمات ممنوع، Regex محدود با ماشین حالت بدون backtracking، ساعت سکوت تهران، Flood، تکرار پیام و شمارنده اخطار؛ مدیران مستثنا فقط شناسه‌های صریحاً پیکربندی‌شده‌اند، نه مدیران شناسایی‌شده از API.
- فرمان‌های `/help`، `/rules`، `/id`، فرمان و FAQ سفارشی، متغیرهای قالب، ساعت کاری، دکمه Simple، منوی چهارسطحی و صفحه‌بندی.
- فرم چندمرحله‌ای با رضایت `/confirm`، انقضای حداکثر ۱۵ دقیقه، مشاهده پاسخ‌های موقت دارای رضایت و حذف با `/cancel`. لغو رضایت `/unsubscribe` حتی با پاسخگویی غیرفعال یا قفل متن پردازش می‌شود.
- اجرای یک نوبت موتور و زمان‌بندی از پنل، Worker خصوصی Node.js با cursor پایدار، lease اتمی، توقف مستقل، backoff خواندن و ممنوعیت ارسال مجدد نتیجه مبهم.
- صف انتشار تنها برای موارد `enabled:true, authorized:true, status:'approved'`؛ زمان آینده هنگام تأیید، مقصد ثبت‌شده، پیش‌نمایش، تکرار محدود و UUID پایدار برای هر اجرای هر مقصد.
- تقویم واقعی شمسی، گزارش اندازه‌گیری‌شده و مقایسه بازه، و دانلود CSV، JSON و XLSX معتبر؛ هیچ آمار ساختگی به‌عنوان داده واقعی نمایش داده نمی‌شود.
- Docker مجزا برای web و worker و workflow آزمون JavaScript در GitHub Actions. اجرای CI پس از push باید جداگانه بررسی شود.

**این کد هنوز روی Supabase واقعی کاربر مستقر نشده است.** برای امکانات جدید سه migration را به ترتیب اعمال و تابع نسخه ۳٫۱ را روی پروژه آزمایشی منتشر کنید. [راهنمای Worker](server/runtime/README.md) برای استقرار خصوصی Node.js/Docker است. GitHub Pages خود Worker، Webhook یا زمان‌بندی دائمی اجرا نمی‌کند.

همه ۱۵۰ قابلیت کامل نشده‌اند. Webhook، RBAC، MFA، دستیار اختیاری AI، Upload کامل، پشتیبان کامل پایگاه داده و عملیات بدون پشتیبانی مستند API همچنان محدودیت دارند. [جدول آخرین وضعیت](docs/FEATURES.md) وضعیت هر مورد و نتیجه بررسی را ثبت می‌کند.

## اجرای توسعه

Node.js نسخه ۲۰ یا بالاتر کافی است؛ برنامه Frontend وابستگی نصب‌شدنی ندارد.

```bash
cd /workspace/rubika_bot
node scripts/serve.mjs
```

سرور توسعه روی پورت `4173` شروع می‌شود؛ هم مسیر ریشه و هم مسیر پروژه `/rubika_bot/` را برای آزمایش GitHub Pages ارائه می‌کند. این سرور فقط فایل عمومی سرو می‌کند و API روبیکا نیست. برای پورت دیگر از متغیر `PORT` استفاده کنید. توکن ربات فقط بعد از واردکردن در پنل به تابع Supabase ارسال می‌شود.

در محیط ابری از checkout موجود استفاده کنید؛ هر task ایزوله است و ساخت Git worktree برای این پروژه لازم نیست.

## انتشار GitHub Pages

در GitHub بخش **Settings → Pages**، گزینه **Deploy from a branch**، شاخه `main` و پوشه `/ (root)` را انتخاب کنید. تمام فایل‌های عمومی با مسیر نسبی ارجاع داده شده‌اند و فایل `.nojekyll` وجود دارد. آدرس پروژه پس از انتشار:

`https://mozdbaranarshiya.github.io/rubika_bot/`

پس از قرارگرفتن فایل‌ها در GitHub، انتشار سایت به فعال‌بودن GitHub Pages روی شاخه و پوشه درست وابسته است. این کد تنظیمات Pages مخزن را خودکار تغییر نمی‌دهد. PWA در HTTPS و مرورگر سازگار نصب می‌شود. Service Worker تنها فایل‌های عمومی را Cache می‌کند؛ درخواست POST، توکن و داده شخصی Cache نمی‌شوند.

## اتصال سرویس

نشانی اولیه همان تابع نسخه قبلی است:

`https://efibfevyiepkwpnobaro.supabase.co/functions/v1/rubika-panel`

برای فعال‌شدن امکانات جدید، ابتدا migration و تابع JavaScript نسخه ۳ را طبق راهنمای سرور روی پروژه آزمایشی منتشر کنید. سپس از همه ربات‌ها خارج شوید و نشانی تابع جدید را در صفحه تنظیمات وارد کنید. HTTPS الزامی است؛ HTTP فقط برای توسعه روی localhost پذیرفته می‌شود. Origin پنل در تنظیم سرور باید `https://mozdbaranarshiya.github.io` باشد؛ مسیر `/rubika_bot/` بخشی از Origin نیست.

داده‌های سرویس قبلی خودکار مهاجرت نمی‌کنند؛ پیش از تعویض سرویس پشتیبان تنظیمات بگیرید. نسخه ۳ جدول‌های مستقل دارد و migration به جدول‌های قبلی دست نمی‌زند. بازیابی چند مقصد تراکنش اتمیک نیست و نتیجه جزئی در صورت خطا اعلام می‌شود. پشتیبان فعلی فقط تنظیمات مقصدها را شامل می‌شود؛ برای پشتیبان کامل پایگاه داده از ابزار Supabase استفاده کنید.

## امنیت و عملیات پیام

توکن در فایل پروژه، URL پنل، LocalStorage، SessionStorage، IndexedDB، Cache یا پایگاه داده برنامه قرار نمی‌گیرد. فقط در حافظه همان تب است و با خروج یا تازه‌سازی پاک می‌شود. نشانی عمومی سرویس و انتخاب ظاهر تنها تنظیمات ذخیره‌شده مرورگرند. توکن را در Git، Issue، چت، Screenshot، فایل JSON یا عنوان مقصد ننویسید. اسرار سرور را فقط در تنظیمات امن Supabase وارد کنید؛ نمونه نام‌ها در [server/.env.example](server/.env.example) است.

CORS به‌تنهایی کنترل دسترسی نیست. سرور جدید در هر درخواست اعتبار توکن را با `getMe` بررسی می‌کند، داده‌ها را بر اساس شناسه ربات تأییدشده جدا می‌کند، RLS و محدودیت نرخ دارد و تاریخچه فقط خواندنی ثبت می‌کند. ورود توکنی برای مالک ربات است؛ دفتر مخاطبان نقش امنیتی ایجاد نمی‌کند.

ارسال پیام نیازمند ثبت مقصد و تأیید مجوز است. حذف، ویرایش و فوروارد تأیید جدا دارند. برای هر عملیات یک UUID نگه داشته می‌شود. پس از نتیجه نامشخص یا موفقیت تأییدشده با ثبت ناقص، تلاش مشابه خودکار تکرار نمی‌شود؛ ابتدا مقصد را بررسی کنید. کلیک «مقصد را بررسی کردم» فقط مانع نشست را پس از تأیید شما باز می‌کند و پیام ارسال نمی‌کند. تازه‌سازی حافظه نشست و این UUIDها را پاک می‌کند؛ پیش از تلاش جدید بعد از تازه‌سازی، حتماً مقصد را بررسی کنید.

API روبیکا طبق قرارداد مرجع توکن را در مسیر HTTPS دریافت می‌کند؛ حفاظت و حذف اطلاعات حساس از لاگ‌های زیرساخت باید هنگام انتشار بررسی شود. کد برنامه TLS را غیرفعال نمی‌کند و خطای خام/URL توکن‌دار را ثبت نمی‌کند.

## آزمون‌ها

تست‌های سرور با Node و بدون توکن واقعی:

```bash
npm test
```

آزمون PostgreSQL اختیاری است و فقط پایگاه داده موقت Docker را می‌سازد و پاک می‌کند:

```bash
npm run test:sql
```

ابزار مرورگر خارج از checkout نصب می‌شود:

```bash
npm install --prefix /tmp/rubika-tools --cache /tmp/rubika-npm-cache --save-exact --no-audit --no-fund playwright@1.58.2
# سرور توسعه باید از قبل روی پورت 4173 در حال اجرا باشد.
npm run test:browser
npm run test:pwa
```

اسکریپت به‌طور پیش‌فرض از Chromium موجود در `/usr/bin/chromium` استفاده می‌کند. مسیرهای دیگر با `CHROMIUM_PATH` و `PLAYWRIGHT_MODULE` قابل تنظیم‌اند. آزمایش مرورگر فقط روی سرور محلی با API آزمون اجرا می‌شود و هیچ پیام واقعی به روبیکا نمی‌فرستد. تصاویر و نتایج در `/tmp/rubika-validation` تولید می‌شوند. نتیجه آزمون‌ها و محدودیت اتصال زنده در [docs/VALIDATION.md](docs/VALIDATION.md) آمده است.

## ساختار

- `index.html` و `assets/style.css`: پوسته فارسی، RTL و طراحی واکنش‌گرا.
- `assets/js/app.js`: صفحات و جریان‌های مدیریتی.
- `assets/js/api.js`: ارتباط امن با سرویس و مدیریت خطا.
- `assets/js/model.js`: تنظیمات، تاریخ تهران، خروجی گزارش و اعتبارسنجی بازیابی.
- `assets/fonts/`: فونت Vazirmatn و مجوز OFL.
- `assets/icons/`: آیکون‌های SVG و PNG در اندازه‌های مختلف.
- `manifest.webmanifest` و `sw.js`: نصب PWA و Cache فقط فایل‌های عمومی.
- `server/`: سرویس JavaScript، migration، قرارداد API و آزمون‌ها.
- `scripts/`: سرور توسعه JavaScript و آزمون مرورگر.
- `docs/`: بررسی ۱۵۰ قابلیت و شواهد اعتبارسنجی.

مراجع درخواستی برای بررسی: [yamarg/rubika_bot](https://github.com/yamarg/rubika_bot) و [AliRn76/rubika-bot](https://github.com/AliRn76/rubika-bot). کد Python آنها اجرا یا وارد پروژه نشده است. فایل `requirements.txt` در checkout حاضر وجود ندارد؛ تداخل‌های گیت مربوط به مرجع خارجی در گزارش بررسی ثبت شده‌اند.
