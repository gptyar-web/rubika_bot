# Rubika Group Manager — Admin Dashboard

پنل مدیریت فارسی و واکنش‌گرای ربات روبیکا، برای استقرار در GitHub Pages.

## وضعیت کنونی
- ورود با توکن Rubika Bot API، با اعتبارسنجی سمت سرور در Supabase Edge Functions.
- رمز/توکن در GitHub، Supabase Database، LocalStorage و SessionStorage ذخیره نمی‌شود؛ تا بسته‌شدن یا تازه‌سازی صفحه فقط در حافظه همان تب باقی می‌ماند.
- ثبت گروه‌ها با شناسه، مدیریت قفل‌ها، ضداسپم، قوانین، خوشامدگویی، ساعت سکوت و محدودیت اخطار.
- تنظیمات در جدول‌های `rubika_panel_bots` و `rubika_panel_groups` در Supabase ثبت می‌شوند.
- دیتابیس RLS دارد و دسترسی عمومی مستقیم به جداول ممنوع است.
- **این پنل فعلاً تنظیمات را فقط ذخیره می‌کند؛ به موتور Python 1.1 وصل نیست و تغییرات در گروه اعمال نمی‌شوند.**
- موتور Webhook و خودکارسازی کامل برای نسخه ۲ در ادامه اضافه خواهند شد.

## راه‌اندازی GitHub Pages
در Settings → Pages گزینه Deploy from a branch را انتخاب کنید؛ Branch = `main` و Folder = `/ (root)`. سپس آدرس سایت:
https://mozdbaranarshiya.github.io/rubika_bot/

## امنیت
توکن را هرگز در فایل‌های عمومی، issue، commit، آدرس لینک یا اسکرین‌شات قرار ندهید. دقت کنید هر فردی که توکن را بداند، مالک سطح دسترسی آن ربات خواهد بود. ورود صرفاً با توکن برای محیط تک‌مالک مناسب است؛ برای چندمدیر و محیط حساس، ورود با Supabase Auth و سیاست دسترسی مجزا توصیه می‌شود. چون توکن در URL مسیر درخواست `getMe` به Rubika ارسال می‌شود، لاگ‌های ورودی زیرساخت ممکن است مسیر را ثبت کنند. دسترسی و حفاظت از لاگ‌ها باید بررسی شود.

## معماری
- `index.html`: پنل GitHub Pages.
- Supabase Edge Function: `rubika-panel`؛ اعتبارسنجی از `getMe` در API رسمی روبیکا، و CRUD تنظیمات.
- Supabase Postgres: جدول‌های مجزا، با RLS و فقط دسترسی service_role.
- تابع فقط origin سایت GitHub Pages را در CORS مجاز می‌کند. **CORS به‌تنهایی محافظ امنیتی نیست؛ اعتبارسنجی توکن در هر درخواست انجام می‌شود.**
