# بررسی مخزن اولیه

مبنای بررسی: commit اولیهٔ `4733ee37363ed1c2c57e270bae53bd07900b0a23` در `yamarg/rubika_bot`، همراه فایل‌های `README.md`، `requirements.txt`، تمام ماژول‌های `group-manager` و ساختار فایل‌های ریشه. مستندات رسمی `rubika.ir/botapi` و کد Adapter مخزن مکمل `AliRn76/rubika-bot` نیز بررسی شدند.

## یافته‌ها و تغییرها

- مخزن اولیه HTML، CSS، پنل وب یا پیکربندی Pages نداشت؛ برنامهٔ `rubpy.Client` برای اتصال حساب بود و با Bot API مبتنی بر توکن یکسان نیست. اتصال امن این دو معماری بدون مهاجرت ممکن نیست؛ پنل جدید از Bot API رسمی در ماژول مستقل استفاده می‌کند.
- تداخل merge در `requirements.txt`، `.gitignore` و `group-manager/help.txt` وجود داشت و رفع شد. هر دو بخش help یکسان بودند؛ یک نسخه حفظ شد.
- راهنمای قبلی به `bot.py` اشاره می‌کرد که در درخت مخزن وجود نداشت. راهنمای فعلی مسیر اجرای پنل و مرز کد قدیمی را روشن کرده است.
- کد قبلی همزمان handlerهای sync و async دارد و در ماژول‌های مختلف `Update` و `Updates` وارد می‌کند. برخی تابع‌ها با نام تکراری تعریف شده‌اند و چند مسیر پیش از بررسی وجود reply/record، مشخصات آن را می‌خوانند. این موارد برای کد قدیمی نیازمند مهاجرت و آزمون جدا هستند؛ سالم یا اجراشده اعلام نشده‌اند.
- `SQLAlchemy`، `APScheduler` و `rubpy` بدون نسخه و با تداخل ثبت شده بودند. تداخل رفع شد؛ majorهای قابل اتکای API مورد استفادهٔ APScheduler/SQLAlchemy کران‌گذاری شدند. نسخهٔ سازگار `rubpy` بدون اجرای مستقل ادعا نشده است. وابستگی‌های مستقیم دیگری که import شده بودند نیز فهرست شدند.
- یک توکن کامنت‌شده از فایل اصلی حذف شد. اعتبارنامهٔ منتشرشده در تاریخچهٔ قبلی با این حذف از تاریخچه پاک نمی‌شود؛ تعویض آن در سرویس صادرکننده لازم است.
- فایل‌هایی با کاربرد نشست/داده در ریشه موجودند. بدون خواندن یا اجرای محتوای باینری آن‌ها، خروجی انتشار با allowlist ساخته شده تا به سایت راه پیدا نکنند. فایل‌های قدیمی حذف نشده‌اند.
- قفل‌ها، فیلتر کلمه، یادگیری پاسخ، اخطار و بعضی عملیات مدیریت در کد اولیه وجود دارند. وجود کد دلیل تأیید اجرایی نیست؛ همه در ستون «وضعیت قبل از تغییر» جدول ۱۵۰ قابلیت با همین قید آمده‌اند.

## تصمیم فنی

مطابق درخواست جدید کاربر، هیچ Backend پایتون یا وابستگی پایتون برای پنل اضافه نشده است. دادهٔ پنل در IndexedDB رمزگذاری می‌شود، Adapter روبیکا JavaScript است و خروجی Pages فایل ایستا است. واسط اختیاری CORS نیز JavaScript است و به‌صورت جداگانه مستقر می‌شود. ویژگی‌هایی که به سرور یا دادهٔ تأییدنشدهٔ API وابسته‌اند در پنل و جدول قابلیت‌ها با محدودیت روشن مشخص شده‌اند.
