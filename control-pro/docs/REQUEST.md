# پرامپت جامع ساخت پنل پیشرفته مدیریت ربات روبیکا با ۱۵۰ قابلیت

## نقش و مأموریت

تو یک توسعه‌دهنده ارشد Full-Stack، متخصص Python، API روبیکا، معماری نرم‌افزار، امنیت، طراحی UI/UX و ساخت داشبوردهای مدیریتی هستی.

می‌خواهم برنامه فعلی من را به یک نرم‌افزار حرفه‌ای، مدرن، زیبا، سریع و کاملاً فارسی برای مدیریت ربات‌های روبیکا تبدیل کنی.

**مخزن اصلی و مرجع پروژه در این آدرس است:**

https://github.com/yamarg/rubika_bot

مخزن مکمل برای بررسی قابلیت‌های Bot API:

https://github.com/AliRn76/rubika-bot

کد پایه، مستندات و برخی قابلیت‌های مدیریت ربات و گروه در این مخازن قرار دارند. ابتدا کدها را دقیق بررسی کن و از قابلیت‌های موجود استفاده کن. هر قابلیتی که وجود ندارد باید به‌صورت اصولی توسعه داده شود.

هیچ‌کدام از ۱۵۰ قابلیت زیر را بدون بررسی کد، جزو قابلیت‌های پیاده‌سازی‌شده مخزن اعلام نکن.

### مرحله اول: بررسی و آماده‌سازی مخزن

ابتدا ساختار پوشه‌ها، ماژول‌ها، کتابخانه‌ها، دستورات، مدل‌های داده، ارتباط با روبیکا و وابستگی‌های پروژه را بررسی کن.

فایل `requirements.txt` را به‌خصوص از نظر نشانه‌های حل‌نشده تداخل گیت بررسی و اصلاح کن. سازگاری نسخه کتابخانه‌های `rubpy`، `APScheduler` و `SQLAlchemy` را بررسی کن.

قابلیت‌ها را به سه دسته تقسیم کن: «موجود و آزمایش‌شده»، «نیازمند توسعه» و «وابسته به پشتیبانی API روبیکا».

کدهای سالم برنامه قبلی را حفظ کن و قابلیت‌های جدید را بدون تخریب قسمت‌های موجود اضافه کن.

## مرحله سوم: طراحی ظاهری فوق‌حرفه‌ای

ظاهر این نرم‌افزار برای من بسیار مهم است. نمی‌خواهم برنامه شبیه یک پروژه آزمایشی یا قالب ساده و قدیمی باشد.

نام پیشنهادی نرم‌افزار: **Rubika Control Pro**

یک هویت بصری اختصاصی، ساده، مدرن و ماندگار طراحی کن.

### طراحی آیکون اختصاصی

برای نرم‌افزار یک آیکون برداری SVG بساز که ترکیبی خلاقانه از حباب گفتگو، نماد ربات و سپر امنیتی باشد.

ویژگی‌های آیکون:

- طراحی مینیمال و حرفه‌ای.
- گوشه‌های نرم و فرم‌های هندسی متعادل.
- استفاده از رنگ بنفش مدرن همراه با فیروزه‌ای.
- قابلیت نمایش در اندازه کوچک و بزرگ.
- پس‌زمینه شفاف برای نسخه اصلی.
- نسخه مخصوص حالت روشن و تاریک.
- خروجی SVG و PNG و favicon.
- آیکون مناسب نصب PWA و صفحه ورود.
- طراحی مستقل، بدون کپی‌برداری از لوگوی رسمی روبیکا.

### فونت اجباری

در تمام صفحات و بخش‌های رابط کاربری از **Vazirmatn** استفاده کن.

فونت باید در عنوان‌ها، دکمه‌ها، جدول‌ها، فرم‌ها، پیام‌های هشدار، نمودارها، منوها و صفحات تنظیمات اعمال شود.

وزن‌های 400، 500، 600 و 700 پشتیبانی شوند.

فونت ترجیحاً به‌صورت محلی و از منبع معتبر همراه برنامه بارگذاری شود تا در حالت آفلاین یا شرایط اینترنت ضعیف نیز بدون مشکل نمایش داده شود.

برای یکپارچگی از خانواده فونت `"Vazirmatn", sans-serif` استفاده کن.

نوشته‌های فارسی باید فاصله‌گذاری صحیح، نیم‌فاصله و ارتفاع خط مناسب داشته باشند. نمایش متن‌های ترکیبی فارسی و انگلیسی، اعداد، مسیرها و کدها نباید جهت صفحه را خراب کند.

### ساختار صفحه اصلی

پنل اصلی باید دارای این قسمت‌ها باشد:

- سایدبار سمت راست با امکان جمع‌شدن.
- نوار بالایی شامل جستجو، اعلان‌ها، وضعیت اتصال و پروفایل مدیر.
- کارت خوشامدگویی زیبا و خلاصه وضعیت سیستم.
- کارت تعداد ربات‌های فعال.
- کارت گروه‌ها و کانال‌ها.
- کارت پیام‌های پردازش‌شده.
- کارت تخلفات و هشدارهای امنیتی.
- نمودار فعالیت روزانه.
- نمودار وضعیت انتشار پست‌ها.
- جدول آخرین فعالیت‌های ثبت‌شده.
- میانبرهای کاربردی برای افزودن ربات، مدیریت گروه، ارسال پست و مشاهده گزارش‌ها.

منوی اصلی شامل داشبورد، ربات‌ها، گروه‌ها، کانال‌ها، پیام‌ها، قفل‌ها، مدیریت تخلفات، اتوماسیون، زمان‌بندی، کاربران، گزارش‌ها، سوابق فعالیت و تنظیمات باشد.

### جزئیات طراحی

از کارت‌های دارای گوشه گرد 16 تا 20 پیکسل، سایه‌های نرم، خطوط جداکننده ظریف، آیکون‌های هماهنگ و فاصله‌گذاری استاندارد استفاده کن.

انیمیشن‌های کوتاه و روان برای بازشدن منوها، نمایش اعلان‌ها، تغییر وضعیت کلیدها و جابه‌جایی صفحات طراحی کن.

از Skeleton Loading برای بارگذاری و Toast برای اعلام نتیجه عملیات استفاده کن.

برای تمام صفحات، وضعیت خالی، وضعیت خطا، وضعیت بارگذاری و وضعیت موفقیت طراحی کن.

در موبایل، سایدبار باید به منوی قابل باز و بسته‌شدن تبدیل شود و فرم‌ها، نمودارها و جدول‌ها به‌درستی نمایش داده شوند.

تمام عناصر تعاملی باید با صفحه‌کلید نیز قابل استفاده باشند و کنتراست رنگی مناسب داشته باشند.

## مرحله چهارم: معماری و فناوری

معماری موجود مخزن را در اولویت قرار بده و بدون دلیل بخش‌های سالم آن را بازنویسی نکن.

در صورت نیاز به ساخت پنل جدید و نبود فناوری مشخص در پروژه، معماری پیشنهادی من:

**Backend:** Python + FastAPI

**Frontend:** Next.js + TypeScript

**UI:** Tailwind CSS و کامپوننت‌های مدرن

**Icons:** Lucide Icons همراه با آیکون اختصاصی برنامه

**Charts:** Recharts

**Database:** PostgreSQL برای محیط اصلی و SQLite برای توسعه محلی

**ORM:** SQLAlchemy همراه با Migration

**Jobs:** APScheduler یا صف وظایف مناسب

**API:** REST با مستندات OpenAPI

**Deployment:** Docker و Docker Compose

**Testing:** Pytest برای Backend و ابزار تست مناسب Frontend

اگر استفاده از یک فناوری باعث ناسازگاری با مخزن فعلی می‌شود، راه‌حل سازگارتر را انتخاب کن و دلیل آن را توضیح بده.

منطق ارتباط با روبیکا را از رابط کاربری و منطق تجاری جدا کن و یک لایه Adapter مستقل بساز.

توکن‌ها و اطلاعات حساس نباید در کد Frontend، مخزن عمومی یا لاگ‌ها افشا شوند.

## مرحله پنجم: قوانین امنیت و سازگاری

فقط از APIها و روش‌های مجاز و قابل تأیید روبیکا استفاده کن.

اگر API روبیکا قابلیتی مثل مسدودسازی کاربر، سنجاق پیام یا مدیریت مستقیم اعضا را ارائه نمی‌کند، نباید برای آن قابلیت جعلی بسازی یا موفقیت غیرواقعی نمایش بدهی.

قابلیت‌های پشتیبانی‌نشده را با وضعیت مشخص «نیازمند پشتیبانی API» نشان بده.

ارسال اعلان‌ها و پیام‌های گروهی باید فقط برای کاربران و مقصدهای دارای رضایت یا مجوز معتبر انجام شود.

از ارسال اسپم، دورزدن محدودیت‌ها، جمع‌آوری اطلاعات خصوصی و دسترسی غیرمجاز جلوگیری کن.

در Backend کنترل سطح دسترسی، اعتبارسنجی داده‌ها، محدودسازی درخواست‌ها، حفاظت در برابر CSRF در صورت استفاده از کوکی، ثبت سوابق امنیتی و مدیریت صحیح نشست‌ها را پیاده‌سازی کن.

برای عملیات خطرناک مانند حذف اطلاعات، مسدودسازی کاربران و تغییر نقش‌ها، تأیید مناسب در نظر بگیر.

## مرحله ششم: استاندارد کیفیت و تحویل

می‌خواهم خروجی نهایی یک برنامه واقعاً قابل اجرا باشد، نه صرفاً طراحی ظاهری یا صفحات نمایشی.

الزامات نهایی:

1. تمام صفحات اصلی باید به Backend واقعی متصل باشند.
2. هیچ دکمه‌ای بدون عملکرد واقعی یا پیام وضعیت مناسب باقی نماند.
3. اطلاعات باید به‌صورت پایدار در پایگاه داده ذخیره شوند.
4. قابلیت‌های موجود مخزن باید حفظ شوند.
5. امکانات جدید به‌صورت ماژولار توسعه داده شوند.
6. تمام وابستگی‌ها باید سالم و قابل نصب باشند.
7. تست‌های ضروری برای بخش‌های حساس نوشته شوند.
8. اطلاعات محرمانه از طریق متغیرهای محیطی مدیریت شوند.
9. فایل نمونه تنظیمات محیطی ایجاد شود.
10. مستندات نصب، اجرا و توسعه به زبان فارسی نوشته شوند.
11. پروژه باید در حالت توسعه و تولید قابل راه‌اندازی باشد.
12. خروجی شامل فایل‌های واقعی آیکون، فونت، کامپوننت‌ها، صفحات و API باشد.

ابتدا یک جدول وضعیت ۱۵۰ قابلیت ایجاد کن که برای هر مورد، شناسه قابلیت، وضعیت فعلی، فایل یا ماژول مرتبط، وابستگی به API، اولویت و نتیجه تست را نمایش دهد.

سپس پیاده‌سازی را به مراحل کوچک، قابل آزمایش و قابل تحویل تقسیم کن.

اولویت توسعه این باشد:

**اولویت اول:** اصلاح مخزن، اتصال ربات، امنیت، داشبورد و مدیریت پیام‌ها.

**اولویت دوم:** قفل‌ها، مدیریت گروه، تخلفات و اتوماسیون.

**اولویت سوم:** کانال‌ها، انتشار زمان‌بندی‌شده، گزارش‌ها و سیستم پشتیبانی.

**اولویت چهارم:** امکانات پیشرفته، بهینه‌سازی، PWA و تکمیل طراحی بصری.

پس از هر مرحله، قابلیت‌ها را آزمایش کن و مشکلات را برطرف کن.

**اکنون با بررسی واقعی فایل‌ها و معماری مخزن شروع کن، گزارش وضعیت قابلیت‌ها را تهیه کن و سپس مراحل پیاده‌سازی را با کدهای کامل و قابل اجرا پیش ببر.**
