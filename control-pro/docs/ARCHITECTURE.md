# معماری پنل

پنل یک برنامهٔ ایستای ES Modules است. `index.html` و `assets/style.css` پوسته را می‌سازند؛ `js/layout.js` و `js/pages.js` صفحه‌ها را با escapeکردن داده‌های پویا رندر می‌کنند. هیچ متن کاربر به‌عنوان کد یا HTML قابل اجرا پذیرفته نمی‌شود. فونت، آیکون و همهٔ ماژول‌ها محلی‌اند.

## مسیر داده

۱. `js/vault.js` کل مخزن را با Web Crypto رمزگشایی می‌کند و فقط در حافظه نگه می‌دارد.
۲. `js/actions.js` فرم‌ها را اعتبارسنجی می‌کند؛ درخواست‌های عملیاتی را از `js/api.js` عبور می‌دهد.
۳. `js/runtime.js` با `getUpdates` و `offset_id` کار می‌کند. رویداد فقط برای مقصد ثبت‌شده و مجاز پذیرفته می‌شود.
۴. شناسهٔ رویداد پیش از هر اثر بیرونی در مخزن ذخیره می‌شود. رویدادهای تکراری در آرشیو اخیر رد می‌شوند. این طراحی at-most-once را ترجیح می‌دهد؛ در شکست بین checkpoint و اقدام، پاسخ ممکن است انجام نشود و خودکار تکرار نمی‌شود.
۵. `js/moderation.js` قواعد خالص فیلتر و ضداسپم را محاسبه می‌کند. استثناهای مدیران پیش از هر قفل بررسی می‌شوند. پیش‌فرض فقط ثبت تخلف است.
۶. صف انتشار قبل از ارسال `sending` را پایدار می‌کند؛ هر مقصد نتیجهٔ مستقل دارد. قطع صفحه در این مرحله در ورود بعدی `interrupted` می‌شود و نیازمند بازبینی است.
۷. تغییرات دوباره با IV تازه رمزگذاری و در IndexedDB جایگزین می‌شوند. تراکنش با شمارهٔ revision از بازنویسی بی‌خبر دادهٔ زبانهٔ دیگر جلوگیری می‌کند. Web Locks در مرورگرهای پشتیبان، بازکردن همزمان مخزن در دو زبانه را متوقف می‌کند.

## قرارداد API

`RubikaAPI.call(token, method, payload)` تنها متدهای allowlistشده را به endpoint رسمی می‌فرستد. `getMe` باید `data.bot.bot_id` یا شکل سازگار دارای شناسه برگرداند. `getUpdates` باید آرایهٔ `updates` و ادامهٔ `next_offset_id` داشته باشد. ارسال متن، نظرسنجی، فایل، مخاطب و موقعیت باید `message_id` بدهند. فوروارد باید `new_message_id` بدهد. نبود فیلد ضروری خطاست، حتی اگر HTTP 200 باشد.

برای خواندن، خطاهای گذرا با تأخیر افزایشی و سقف تعداد تلاش تکرار می‌شوند. ارسال نوشتنی خودکار تکرار نمی‌شود، زیرا قطع پاسخ ثابت نمی‌کند درخواست اجرا نشده است. پیام خطا عمومی است و بدنهٔ خطای سرور یا URL حاوی توکن در لاگ کپی نمی‌شود.

واسط اختیاری `scripts/relay-worker.js` با همان allowlist کار می‌کند. Origin و کلید دسترسی ضروری‌اند. هیچ URL دلخواهی از درخواست به‌عنوان مقصد upstream پذیرفته نمی‌شود. واسط یک سرویس مستقل اختیاری است و داخل خروجی Pages نیست.

## رمزگذاری و پشتیبان

فرمت نسخهٔ ۱: `{format, version, iterations, salt, iv, data, revision}`. دادهٔ `data` فقط ciphertext احرازشدهٔ AES-GCM است. عبارت رمز ذخیره نمی‌شود. کلید استخراج‌شده non-extractable است. پاک‌کردن مراجع پس از قفل، تضمین پاک‌سازی فیزیکی حافظهٔ JavaScript نیست. قالب و کران‌های پشتیبان پیش از استفاده بررسی می‌شوند؛ صحت ciphertext و رمز با GCM تأیید می‌شود.

پشتیبان کل مخزن است. خروجی گزارش جداگانه فقط رویدادها/سوابق درخواستی را می‌دهد و شامل تنظیمات یا توکن نیست. خروجی CSV کاراکترهای آغازگر فرمول را خنثی می‌کند. Service Worker فقط GETهای هم‌مبدأ در فهرست صریح فایل‌های ایستا را cache می‌کند؛ POST، پاسخ API و دادهٔ مخزن وارد cache نمی‌شوند.

## قابلیت‌های وابسته

Pages نه سرور API، نه Cron، نه receiver وب‌هوک و نه ارائه‌دهندهٔ هویت است. برای تکمیل اجرای دائمی، RBAC/2FA و Webhook، سرویس JavaScript مستقل، پایگاه داده و هویت قابل اعتماد لازم است. این وابستگی‌ها در UI و جدول قابلیت‌ها مشخص‌اند و پشت دکمهٔ موفقیت ساختگی پنهان نمی‌شوند.
