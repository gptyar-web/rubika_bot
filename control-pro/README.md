# Rubika Control Pro

پنل فارسی، راست‌به‌چپ و واکنش‌گرا برای مدیریت بات‌های روبیکا، ساخته‌شده با **HTML، CSS و JavaScript** و قابل انتشار در **GitHub Pages**. اجرای خود پنل به پایتون یا دیتابیس سروری نیاز ندارد. وابستگی‌های npm فقط برای آزمون توسعه هستند.

این نسخه صفحهٔ نمایشی با آمار ساختگی نیست: ثبت بات و مقصد، قالب و کیبورد، قوانین گروه، پاسخ خودکار، پیش‌نویس و تأیید انتشار، صف چندمقصدی، تیکت، گزارش، پشتیبان و بازیابی به مخزن واقعی رمزگذاری‌شده متصل‌اند. عملیات روبیکا از Adapter رسمی API استفاده می‌کنند و تنها پس از پاسخ معتبر موفق اعلام می‌شوند.

**همهٔ ۱۵۰ الزام تکمیل نشده‌اند.** وضعیت هر الزام، سابقهٔ آن در کد قدیمی، فایل مرتبط، اولویت، محدودیت و وضعیت آزمون در [جدول ۱۵۰ قابلیت](docs/FEATURES.md) آمده است. همین جدول داخل پنل قابل جستجو و دریافت به CSV است.

## شروع سریع

با Node.js نسخهٔ ۲۲ یا جدیدتر:

```sh
npm ci
npm test
npm run check
npm run build
npm start
```

نشانی پیش‌نمایش: `http://localhost:4173/rubika_bot/`. فرمان `npm start` ریشهٔ پروژه را سرو می‌کند. برای پیش‌نمایش دقیق خروجی انتشار، `node scripts/serve.mjs dist` را اجرا کنید. فایل `index.html` را با `file://` باز نکنید؛ ES Modules، Web Crypto و PWA به HTTP محلی یا HTTPS نیاز دارند.

۱. مخزن امن را با یک عبارت رمز دست‌کم ۱۲ نویسه بسازید.
۲. توکن بات ایجادشده در BotFather روبیکا را یک‌بار ثبت کنید. اعتبارسنجی با `getMe` پیش‌فرض روشن است. اگر اینترنت/CORS مانع شود، می‌توانید توکن را بدون تأیید آنلاین ذخیره کنید؛ وضعیت «بررسی‌نشده» باقی می‌ماند.
۳. شناسهٔ واقعی `chat_id` مقصد و مجوز ارسال/مدیریت را ثبت کنید. نام کاربری یا لینک دعوت جایگزین این شناسه نیست.
۴. برای دریافت پیام، اجرای قوانین و انتشار زمان‌بندی‌شده، «شروع پردازش» را بزنید.
۵. از تنظیمات، یک پشتیبان رمزگذاری‌شده بگیرید و رمز را در جای امن خودتان نگه دارید.

## انتشار در مخزن فعلی

این نسخه در پوشهٔ `control-pro` مخزن `mozdbaranarshiya/rubika_bot` قرار گرفته و نشانی انتشار آن در GitHub Pages به صورت زیر است:

`https://mozdbaranarshiya.github.io/rubika_bot/control-pro/`

پنل موجود ریشه و بخش `server` حفظ شده‌اند. این دو پنل مستقل‌اند و داده‌های سرویس قبلی خودکار به مخزن رمزگذاری‌شده منتقل نمی‌شوند.

در صورت استفادهٔ مخزن از انتشار شاخهٔ `main` و پوشهٔ ریشه، این پوشه همراه سایت در دسترس قرار می‌گیرد. Workflow اصلی نسخهٔ فعلی حفظ شده و `.github/workflows/control-pro-checks.yml` آزمون این پنل را جداگانه اجرا می‌کند. فایل `control-pro/.github/workflows/pages.yml` الگوی انتشار مستقل بسته است و در این مسیر توسط GitHub اجرا نمی‌شود.

پوشهٔ `dist` نیز خروجی آمادهٔ مستقل است. برای انتشار این پنل به‌عنوان یک مخزن جدا، تنها محتویات `dist` را منتشر کنید؛ فایل‌های نشست و دیتابیس هرگز نباید در خروجی سایت قرار گیرند.

## توکن ذخیره می‌شود، رمز ذخیره نمی‌شود

تمام مخزن، شامل توکن بات، کلید واسط، گفتگوها، متن پیام‌ها و تنظیمات، با **AES-256-GCM** در IndexedDB مرورگر رمزگذاری می‌شود. کلید از عبارت رمز با **PBKDF2-SHA-256، ۶۰۰۰۰۰ دور و salt تصادفی ۱۶ بایتی** استخراج می‌شود. هر ذخیره IV تصادفی تازه دارد. کلید و متن رمزگشایی‌شده فقط در حافظهٔ صفحهٔ باز می‌مانند.

توکن را هر بار وارد نمی‌کنید: هنگام بازگشت فقط مخزن را با عبارت رمز باز کنید. قفل خودکار پس از بی‌فعالیتی، قفل دستی، تغییر رمز و پشتیبان رمزگذاری‌شده در تنظیمات موجودند. رمز در Local Storage، کد عمومی، Service Worker، پشتیبان متنی یا لاگ ذخیره نمی‌شود. Local Storage تنها پوسته و حالت منو را نگه می‌دارد.

این ذخیره‌سازی مختص همین مرورگر و همین origin است. برای انتقال دستگاه، پشتیبان و رمز آن لازم‌اند. پاک‌کردن دادهٔ مرورگر بدون پشتیبان به از دست رفتن مخزن منجر می‌شود. فراموشی رمز راه بازیابی ندارد. فایل پشتیبانِ قبل از تغییر رمز، همچنان به رمز قدیمی نیاز دارد.

مخزن محلی جایگزین ورود چندکاربره، RBAC قابل اعتماد یا 2FA نیست. دستگاه آلوده، افزونهٔ مخرب یا اسکریپت اجراشده در origin می‌تواند به مخزنِ باز دسترسی پیدا کند. روی دستگاه مشترک مخزن را قفل کنید.

## اتصال API و محدودیت CORS

مرجع جاری: [مستندات رسمی API روبیکا](https://rubika.ir/botapi/). نشانی استفاده‌شده `https://botapi.rubika.ir/v3/{token}/{method}` است. [مخزن مکمل](https://github.com/AliRn76/rubika-bot) نیز بررسی شد؛ آدرس قدیمی آن به‌جای مرجع رسمی جاری استفاده نشده است.

اتصال مستقیم فقط وقتی کار می‌کند که سرور روبیکا درخواست مرورگر و CORS origin شما را مجاز بداند. بدون توکن واقعی، اتصال زنده و سیاست CORS حساب شما آزمایش نشده است. پنل خطای شبکه یا CORS را موفقیت نمایش نمی‌دهد.

در صورت نیاز، یک **واسط شخصی JavaScript** در `scripts/relay-worker.js` فراهم شده است. این واسط جداگانه اجرا می‌شود؛ Pages آن را اجرا نمی‌کند. در سرویس سازگار با Cloudflare Workers آن را همراه import مربوط به `js/api.js` bundle و منتشر کنید. تنظیمات نمونه در `wrangler.example.toml` است:

```sh
npx wrangler deploy --config wrangler.example.toml
npx wrangler secret put ACCESS_KEY --config wrangler.example.toml
```

کلید تصادفی قوی دست‌کم ۳۲ نویسه انتخاب کنید. `ALLOWED_ORIGIN` را دقیقاً origin سایت، برای مثال `https://mozdbaranarshiya.github.io`، قرار دهید. سپس نشانی HTTPS واسط و همان کلید را در تنظیمات رمزگذاری‌شدهٔ پنل وارد و مالکیت واسط را تأیید کنید. واسط فقط به endpoint ثابت روبیکا درخواست می‌فرستد، متدها را allowlist می‌کند، Authorization لازم دارد، درخواست را به ۶۴ کیلوبایت محدود می‌کند و خطا یا توکن را لاگ نمی‌کند. این یک واسط CORS است؛ موتور شبانه‌روزی، دیتابیس، گیرندهٔ Webhook، RBAC یا سرویس احراز هویت نیست.

## مرزهای اجرای مرورگر

- با بسته‌شدن صفحه، قفل‌شدن مخزن، قطع اینترنت یا خواب دستگاه، پردازش متوقف می‌شود. مرورگر می‌تواند زبانهٔ پس‌زمینه را کند کند. نصب PWA این محدودیت را برطرف نمی‌کند.
- صفحات GitHub Pages گیرندهٔ POST برای Webhook یا پردازش زمان‌بندی‌شدهٔ دائمی ندارند. این امکانات به یک سرویس اجرایی مستقل نیاز دارند.
- صف، رویداد را پیش از اقدام ثبت می‌کند. اگر ارسال نامشخص شود، نتیجه برای بازبینی نگه داشته می‌شود و ارسال نوشتنی خودکار تکرار نمی‌شود. تضمین exactly-once سراسری وجود ندارد.
- پست بیش از ۱۰ دقیقه عقب‌افتاده بدون تأیید جدید منتشر نمی‌شود. مقصدهای موفق هنگام تکرار دستی دوباره ارسال نمی‌شوند. چند کانال به‌صورت ترتیبی ارسال می‌شوند و تراکنش اتمیک ندارند.
- تاریخ‌ها با تقویم شمسی نمایش داده می‌شوند. ورودی `datetime-local` صریحاً میلادی و به وقت تهران تفسیر می‌شود؛ منطقهٔ زمانی دستگاه بر زمان ذخیره‌شده اثر ندارد. تقویم ماهانهٔ تعاملی ساخته نشده است.
- ارسال متن، پاسخ، ویرایش، حذف، فوروارد، نظرسنجی، موقعیت، مخاطب و فایل با `file_id` پیاده‌سازی شده‌اند. آپلود رسانه و کپشن چندرسانه‌ای هنوز ساخته نشده‌اند.
- قفل نوع تصویر/ویدئو/ویس/GIF و استوری بدون مشخصهٔ مستند API فعال نمی‌شود. مدیران و استثناها دستی ثبت می‌شوند؛ شناسایی خودکار فهرست مدیران، خوشامد ورود اعضا و سنجاق پیام ادعا نشده‌اند.
- الگوهای Regex عمداً به زیرمجموعهٔ محدود بدون گروه‌بندی، escape و کمیت‌گذار محدود شده‌اند تا پیام نامطمئن مرورگر را متوقف نکند.
- آرشیو برای کنترل اندازه محدود است: ۵۰۰۰ پیام، ۱۰۰۰۰ رویداد/شناسه، ۲۰۰۰ تخلف و ۱۵۰۰ لاگ. آمار محدود به همین آرشیو است و شمارش مادام‌العمر نیست.
- CSV و JSON آماده‌اند. CSV در Excel باز می‌شود؛ خروجی بومی XLSX، مقایسهٔ دو بازه، دستیار AI و کمپین انبوه هنوز پیاده‌سازی نشده‌اند.

## کد قبلی

پوشهٔ `group-manager` به‌عنوان کد قدیمی حفظ شده و در پنل جدید import یا اجرا نمی‌شود. تداخل‌های واقعی `requirements.txt` و `group-manager/help.txt` رفع شده‌اند و توکن کامنت‌شده از کد حذف شده است. حذف از نسخهٔ جاری، سابقهٔ گیت را پاک نمی‌کند؛ هر اعتبارنامه‌ای که قبلاً عمومی شده باید در سرویس صادرکننده تعویض شود.

`requirements.txt` فقط برای کد قدیمی است. کران major برای APScheduler 3 و SQLAlchemy 2 درج شده؛ `rubpy` به دلیل ترکیب handlerهای sync و async و تفاوت `Update/Updates` در کد قدیمی عمداً نسخهٔ «تأییدشده» ندارد. سازگاری اجرایی پایتون و اتصال حساب قدیمی آزمایش نشده و این بخش آمادهٔ اجرای production اعلام نمی‌شود. وابستگی‌های مستقیمِ استفاده‌شده در فایل‌ها نیز فهرست شده‌اند؛ پنل Pages هیچ‌یک را مصرف نمی‌کند.
