# گزارش وضعیت ۱۵۰ قابلیت Rubika Control Pro

این سند هم snapshot اولیه و هم [جدول نهایی کامل](#جدول-نهایی-کامل) را نگه می‌دارد. وضعیت جاری در [feature-status.json](feature-status.json) به‌روز شده و `initialStatus` و `initialEvidence` بدون تغییر باقی مانده‌اند. گزارش نهایی بر پایه آزمون محلی است؛ هیچ `productionVerified` مقدار true ندارد.

این جدول پیش از پیاده‌سازی از فایل‌های واقعی مخزن انتخاب‌شده تهیه شده است. فیلدهای `initialStatus` و `initialEvidence` در [feature-status.json](feature-status.json) snapshot اولیه را حفظ می‌کنند؛ نتیجه توسعه و آزمایش بعداً جداگانه ثبت می‌شود. وضعیت «جزئی و آزمایش‌نشده» زیرمجموعه «نیازمند توسعه» است. وجود نام قابلیت در README یا یک کلید روشن/خاموش، اثبات اعمال آن در روبیکا نیست. هیچ قابلیت در snapshot اولیه «موجود و آزمایش‌شده» نیست.

## نتیجه بازرسی اولیه

- checkout انتخاب‌شده فقط `index.html` و `README.md` داشت؛ backend، migration، تست، manifest یا lockfile داخل آن نبود. README صریحاً ذخیره تنظیمات بدون موتور اجرای ربات را اعلام می‌کرد.
- اتصال به تابع Supabase خارجی، ورود تک‌ربات و فرم تنظیمات گروه دیده شد. سورس آن تابع در checkout نبود و با توکن واقعی آزمایش نشده بود.
- مرجع [yamarg/rubika_bot](https://github.com/yamarg/rubika_bot) در commit `4733ee37363ed1c2c57e270bae53bd07900b0a23` بررسی read-only شد. `requirements.txt` و `group-manager/help.txt` نشانه‌های حل‌نشده merge دارند. `rubpy`، `apscheduler` و `sqlalchemy` بدون نسخه‌اند؛ نصب یا سازگاری آن‌ها تأیید نشده است. README مسیر `bot.py` را معرفی می‌کند اما نقطه ورود موجود `group-manager/main.py` است.
- مرجع yamarg از `rubpy.Client` و نشست حساب کاربری استفاده می‌کند. روش‌های `ban_member`، `is_admin`، `set_group_admin` و metadata آن به Bot API قابل تعمیم نیستند. هیچ کد Python در این توسعه اجرا یا نصب نشد. به درخواست کاربر، پیاده‌سازی HTML، CSS و JavaScript خواهد بود.
- مرجع [AliRn76/rubika-bot](https://github.com/AliRn76/rubika-bot) در commit `203da2e585f03d6b2cef96cbd7a68b471e010db7` بررسی شد. درخواست multipart آن TLS را خاموش می‌کند و برخی مثال‌های docs نام متد اشتباه دارند؛ این رفتارها نباید منتقل شوند. روش معتبر فعلی باید با مستندات رسمی و پاسخ واقعی تأیید شود.
- دریافت صفحه رسمی `https://rubika.ir/botapi` با HTTP 403 مواجه شد. جدول وابستگی API را بر مبنای مرجع مشخص‌شده ثبت می‌کند، نه ادعای تست عملی روبیکا. هیچ پیام واقعی ارسال، حذف یا منتشر نشده است.

## حدود پشتیبانی مستند API

در `AliRn76/rubika_bot/requests.py` روش‌های `getMe`، `getChat`، `getUpdates`، `sendMessage`، `editMessageText`، `deleteMessage`، `forwardMessage`، `sendPoll`، `sendLocation`، `sendSticker`، `sendContact`، `requestSendFile`، `sendFile`، `getFile`، `setCommands`، `editMessageKeypad`، `editChatKeypad` و `updateBotEndpoints` موجود است. endpoint مرجع `https://messengerg2b1.iranlms.ir/v3/{token}/{method}` است و باید فقط سمت سرور استفاده شود. توکن نباید در لاگ مسیر URL ثبت شود.

مدل `Message` دارای `file_id/file_name/size` است، اما نوع قطعی رسانه ندارد. `requestSendFile` در مرجع فقط File، Image، Voice، Music و Gif را فهرست می‌کند؛ Video و caption آن تأیید نشده‌اند. `Update` رویداد عضویت گروه ندارد و `getChat` اطلاعات تعداد اعضا/فهرست مدیران ندارد. اخراج، مسدودسازی، محدودسازی، سنجاق پیام و تغییر تنظیمات واقعی گروه مستند نیستند. باید در رابط وضعیت روشن و پاسخ خطای مناسب داشته باشند.

## مراحل قابل تحویل

۱. پایه قابل اجرا: پنل فارسی HTML/CSS/JavaScript برای GitHub Pages، اتصال امن به سرور JavaScript، Adapter با فهرست مجاز روش‌ها، پایگاه داده با RLS و آزمون‌های محلی حساس. ورود یا ارسال واقعی فقط با توکن معتبر و سرویس مستقر سنجیده می‌شود.

۲. مدیریت تنظیمات: مقصدهای مجاز، قوانین و قفل‌ها، فرم‌های تنظیمات، سوابق و پشتیبان‌گیری. ذخیره تنظیمات با اجرای قفل، اخطار یا اتوماسیون تفاوت دارد؛ تا وجود موتور مستقلِ آزمایش‌شده، وضعیت اجرا باید صریحاً غیرفعال بماند.

۳. محتوای پایدار: پیش‌نویس، قالب، صف، تیکت، رضایت مشترک و گزارش. زمان‌بندی مستقل مرورگر، پاسخ خودکار و انتشار دوره‌ای به worker/cron و آزمون اجرایی نیاز دارند؛ ساختن رکورد به‌تنهایی این موارد را کامل نمی‌کند.

۴. زیرساخت پیشرفته: RBAC واقعی، MFA، Webhook با تأیید اصالت، رمزگذاری توکن برای پردازش مستقل، گزارش Excel واقعی، تکمیل فرم‌های مکالمه و تست استقرار. هر عملیات وابسته به API تنها پس از اثبات متد و مجوز فعال می‌شود.

## نتیجه نسخه ۳٫۰ (پیش از توسعه موتور)

بازبینی پس از پیاده‌سازی در ۱۴ اکتبر ۲۰۲۶، با تاریخ نمایش به وقت تهران انجام شد. پنل HTML/CSS/JavaScript برای GitHub Pages و سرور JavaScript جداگانه آماده‌اند. **تمام ۱۵۰ قابلیت تکمیل نشده‌اند.** جدول زیر همه شناسه‌ها، اجزای آماده، محدودیت‌ها و شواهد آزمون را نشان می‌دهد. ورود، پیام‌رسانی و داده پایدار هنوز به استقرار سرویس نسخه ۳ و آزمون مجاز واقعی نیاز دارند.

|---|---:|

۲۰ تست Node با Rubika/DB جعلی و ۲۲ گروه آزمون مرورگر و static با API fixture گذشتند. آزمون migration، RLS، منع دسترسی عمومی، rate limit، claim همزمان، replay و یکتایی رویداد روی PostgreSQL واقعی موقت محلی نیز گذشت. آزمون PWA مستقل، فعال‌شدن service worker، Cache فقط ۱۱ asset عمومی GET و reload آفلاین داشبورد فارسی را با صفر خطای JS تأیید کرد. این بررسی‌ها جای آزمون مقصد Rubika یا پروژه Supabase واقعی نیستند؛ هیچ پیام واقعی ارسال یا حذف نشده و انتشار Pages/Supabase انجام نشده است.

موتور دائمی رویداد، اعمال قفل و ضداسپم، اخطار، Webhook، زمان‌بندی، اتوماسیون، RBAC و MFA ساخته نشده‌اند. کلید روشن/خاموش یا رکورد ذخیره‌شده این قابلیت‌ها فقط تنظیم/پیش‌نویس است. موارد دارای وابستگی API تأییدنشده حفظ شده‌اند؛ upload/caption، XLSX، رمزگذاری پایدار توکن، پشتیبان کامل DB و Docker استقرار برنامه نیز تکمیل نیستند.

«موجود و آزمایش‌شده (محلی)» فقط دامنه آزمون نوشته‌شده در هر ردیف را بیان می‌کند. مثلاً آزمون موبایل/دسکتاپ، اثبات همه دستگاه‌ها نیست؛ Cache manifest، اثبات نصب سیستم‌عامل نیست؛ فهرست logs تا ۵۰۰ رکورد، مجموع کل پیام‌های پردازش‌شده نیست. جزئیات اجرا و محدودیت‌ها در [VALIDATION.md](VALIDATION.md) آمده است. همه ۱۵۰ ردیف `productionVerified=false` دارند.

## نسخه ۳٫۱ — موتور و امکانات تکمیلی

در ۱۵ اکتبر ۲۰۲۶ موتور JavaScript، Worker خصوصی، توقف مستقل، اجرای قوانین مستند، پاسخ و دستورات سفارشی، منو/فرم دارای رضایت، صف تأییدشده، تکرار محدود برنامه، تقویم شمسی و XLSX واقعی اضافه شدند. وضعیت زیر آخرین وضعیت است؛ جدول‌های قبلی برای حفظ سابقه باقی مانده‌اند. مقدار `productionVerified` برای هر ۱۵۰ مورد false است.
