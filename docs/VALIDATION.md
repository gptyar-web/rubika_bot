# نتیجه بررسی و اعتبارسنجی

بررسی نهایی در ۱۴ اکتبر ۲۰۲۶ انجام شد. پنل از HTML، CSS و JavaScript استفاده می‌کند و سرور اختیاری نیز JavaScript است؛ کد Python اجرا، نصب یا به این پروژه اضافه نشده است.

## بررسی‌های موفق

| بررسی | نتیجه | حدود نتیجه |
|---|---|---|
| `npm test` | ۲۰ تست سرور، ۲۰ پاس، صفر شکست/Skip | Adapter و Handler با API/DB آزمون؛ این تست‌ها اتصال زنده روبیکا نیستند |
| `node scripts/smoke.mjs` | ۲۲ گروه بررسی مرورگر/فایل، همه موفق؛ صفر استثنای JavaScript | Chromium واقعی، API آزمون رهگیری‌شده؛ هیچ پیام واقعی ارسال نشده |
| `node scripts/pwa.mjs` | موفق | Service Worker واقعی فعال، ۱۱ فایل عمومی GET در Cache، بارگذاری آفلاین پوسته فارسی، بدون Cache داده API؛ صفر خطای مرورگر |
| SQL Integration | موفق | PostgreSQL 17 موقت Docker، اجرای دوباره migration، هفت جدول RLS، منع نقش عمومی و RPC، محدودیت نرخ اتمی، ۱۰ ادعای هم‌زمان عملیات با تنها یک برنده، بازیابی نتیجه و جلوگیری از رویداد تکراری |
| Deno 2.2.4 | بررسی کد تابع موفق | بررسی JavaScript در runtime سرور؛ انتشار Supabase نیست |
| اسکریپت نصب ذخیره‌شده | اجرا با exit 0 | Playwright نسخه ثابت 1.58.2 بیرون checkout، بررسی Node/Chromium، syntax و تست سرور؛ اجرای دوباره آن موفق بود |
| فایل‌های مخزن | `git diff --check` موفق | تغییرات درخواست‌شده در برنامه و فایل‌های تازه؛ نبود conflict markers در فایل‌های پروژه و نبود وابستگی Python |

## جریان‌های بررسی‌شده در مرورگر

- شروع فارسی و RTL بدون ربات، ورود نامعتبر و پاک‌شدن ورودی توکن، درخواست اتصال بدون توکن، ورود معتبر در API آزمون.
- Escape عنوان دریافتی و پیش‌نمایش پیام، عدم اجرای HTML ورودی و عدم قرارگرفتن توکن در URL، LocalStorage یا SessionStorage.
- ذخیره قوانین و محدودیت گروه، حفظ کلیدهای افزوده‌شده در تنظیمات سرور، جلوگیری از ارسال عدد خارج از بازه.
- ثبت مقصد فقط با تأیید مجوز؛ حذف قابل لغو و حذف پس از تأیید.
- جداسازی مقصدها و تنظیمات دو ربات، خروج مستقل و پاک‌شدن نشست با تازه‌سازی.
- ارسال پیام فقط با مجوز و توکن ربات انتخاب‌شده؛ حذف نتیجه موفق قبلی هنگام خطای ارسال.
- نگهداری شناسه عملیات نامشخص یا موفق با ثبت ناقص؛ جلوگیری از تلاش تکراری همان محتوا تا تأیید صریح بررسی مقصد. تأیید بررسی مقصد خودش پیام ارسال نمی‌کند.
- تأیید دوم برای عملیات حساس پیام و Polling فقط با کلیک، همراه ادامه offset سرویس.
- زمان برنامه به وقت تهران ذخیره و نمایش می‌شود؛ آزمون با منطقه زمانی دستگاه Los Angeles نیز همان ISO را تأیید کرد. برنامه فقط پیش‌نویس است.
- پشتیبان تنظیمات بدون توکن، رد بازیابی با شناسه تکراری پیش از تغییر داده، منع تغییر Endpoint در نشست فعال.
- نمایش و جستجوی تمام ۱۵۰ قابلیت، تم روشن/تاریک و موبایل ۳۹۰ پیکسل بدون اسکرول افقی کل صفحه.

اشکال عرض جدول در موبایل در بررسی نخست پیدا و با اصلاح حداقل عرض Grid/Panel رفع شد؛ آزمون کامل بعد از اصلاح موفق بود. ایرادهای آزمون PWA برای انتظار حالت `activated` و انتظار نام حساب مخفی در موبایل نیز در ابزار آزمون اصلاح شدند؛ assertion حذف یا دور زده نشد.

## اتصال واقعی و انتشار

دسترسی خواندنی Git مخزن با احراز هویت موجود موفق بود. در بررسی متغیرها، تنها نام‌های لازم بررسی شدند؛ هیچ مقدار محرمانه چاپ یا در فایل نوشته نشد. توکن روبیکا و کلیدهای استقرار Supabase در اختیار این کار نبودند.

در تلاش اتصال بدون توکن به Endpoint موجود، Proxy محیط پاسخ CONNECT HTTP 403 داد؛ درخواست مستقیم Node نیز DNS `EAI_AGAIN` داشت. صفحه مستندات رسمی روبیکا HTTP 403 داد. این‌ها نتیجه مشاهده‌شدهٔ شبکه‌اند و اثبات خرابی برنامه یا نامعتبر بودن توکن نیستند. تست Production `getMe`، ذخیره روی Supabase واقعی و عملیات پیام واقعی اجرا نشده است.

پیش‌نویس محیط با `install_script` و `start_skill` ذخیره شد. سه دامنه موردنیاز به Allowlist سفارشی اضافه شدند و Presetهای قبلی حفظ شدند:

- `efibfevyiepkwpnobaro.supabase.co`
- `rubika.ir`
- `messengerg2b1.iranlms.ir`

ذخیره پیش‌نویس، اسکریپت را اجرا نمی‌کند و شبکه جاری یا انتشار را تضمین نمی‌کند. برای فعال‌شدن پیکربندی جدید، تنظیمات محیط را بازبینی و ذخیره و سپس محیط را Publish کنید. بازسازی در یک task تازه در این کار آزمایش نشده است.

انتشار GitHub Pages، استقرار تابع جدید Supabase، ورود با توکن واقعی و آزمون در مقصد دارای مجوز باقی است. راهنمای [سرور](../server/README.md) مراحل امن را توضیح می‌دهد. کلیدها فقط در تنظیمات امن Supabase وارد شوند؛ آنها را به چت، Git یا فایل‌های عمومی نفرستید. جدول‌های نسخه ۳ مستقل‌اند و داده نسخه قبلی خودکار منتقل نمی‌شود.

## محدودیت‌های توسعه

تمام ۱۵۰ قابلیت تکمیل نشده‌اند. موتور اجرای مدیریت گروه، قفل‌ها و اتوماسیون، زمان‌بندی دائمی، Webhook، RBAC و ورود دومرحله‌ای هنوز پیاده‌سازی نشده‌اند؛ ذخیره تنظیمات یا پیش‌نویس به‌معنای اجرای آنها نیست. Upload رسانه، Caption فایل، تقویم انتخاب تاریخ شمسی، خروجی XLSX و پشتیبان کامل DB نیز کامل نیستند. محدودسازی، اخراج، مسدودسازی و سنجاق پیام نیازمند پشتیبانی تأییدشده API هستند. جزئیات هر مورد در [FEATURES.md](FEATURES.md) ثبت شده است.

## بررسی نسخه ۳٫۱ — ۱۵ اکتبر ۲۰۲۶

گزارش بالا سابقهٔ نسخه ۳٫۰ است. نتیجهٔ جدید پس از توسعه موتور:

| بررسی | نتیجهٔ فعلی |
|---|---|
| `npm test` | ۸۶ تست سرور + ۸ تست مستقل تقویم و XLSX، همه موفق؛ صفر Fail/Skip |
| `npm run test:browser` | ۲۲ گروه بررسی پایه + ۱۳ گروه بررسی جدید در Chromium واقعی، همه موفق |
| `npm run test:pwa` | Worker مرورگر فعال، ۱۴ فایل عمومی GET، بارگذاری آفلاین همراه اجرای JavaScript و بدون Cache API موفق |
| `npm run test:sql` | هر دو مجموعه PostgreSQL موقت موفق؛ migrationهای ۱، ۲ و ۳، دوازده جدول RLS و رقابت هم‌زمان lease/event/job بررسی شدند |
| Docker | دو target مجزا build شدند؛ worker و engine بدون شبکه/اعتبارنامه import شدند؛ web غیر root و read-only با مسیرهای عمومی و منع فایل خصوصی بررسی شد |
| GitHub Actions | workflow آماده است؛ نتیجه اجرای آن پس از push باید جداگانه مشاهده شود |

موارد تازهٔ بررسی‌شده شامل رضایت صریح قبل از مدیریت و پاسخ، مقصد ثبت‌شده، جلوگیری از حذف تکراری، ثبت شمارنده بدون متن دریافتی، quiescence قبل از فعال‌سازی، ساعت سکوت تهران، لغو رضایت و حذف نشست حتی با قفل متن، lease گمشده و شکست heartbeat پیش از ارسال، توقف مستقل ربات، cursor پس از حسابرسی کامل رویداد، immutability نتیجه job، رد snapshot/زمان/مقصد دست‌کاری‌شده، توقف تکرار در نتیجه نامشخص، منوی تو در تو، صفحه‌بندی callback، فرم دارای رضایت و TTL، Regex با NFA محدود، تاریخ کبیسه، صفحه‌کلید دارای id یکتا، پیش‌نمایش و مجوز انتشار، خروجی Excel واقعی با بررسی CRC آرشیو و XML هستند.

در اصلاحات نهایی، زمان رویداد برای محدودیت Flood به‌کار رفت تا backlog هنگام دریافت، هم‌زمان فرض نشود. پیام قبل از زمان فعال‌سازی جدید مشمول قانون تازه نمی‌شود. کلیک‌های منو به‌عنوان متن تکراری اسپم فرض نمی‌شوند. Worker متوقف‌شده با ضربان معتبر از نظر سلامت فرآیند سالم است و پیام جدید اجرا نمی‌کند. انتخاب تاریخ به منطقه زمانی دستگاه وابسته نیست؛ روز امروز و ساعت انتشار به وقت تهران هستند.

نصب ابزار مرورگر پس از بازسازی محیط مجدداً اجرا شد؛ فرآیندهای سرور باید در هر محیط تازه دوباره آغاز شوند. خطای نوشتن cache Docker در مسیر read-only با تنظیم `BUILDX_CONFIG` و `docker --config` به `/tmp` رفع شد؛ هیچ بررسی TLS یا digest خاموش نشد.

این نتایج آزمایش Rubika واقعی، Supabase واقعی یا استقرار Worker خصوصی را ثابت نمی‌کنند. پشتیبانی مستند API برای هر روش شرط باقی است. Token، کلید service role و `SCOPE_SALT` باید فقط در محیط خصوصی سرویس پیکربندی شوند. GitHub Pages پنل را منتشر می‌کند و سرویس Node دائمی اجرا نمی‌کند. Webhook، RBAC/MFA، Upload کامل، AI اختیاری، backup کامل DB و برخی گردش‌های پیشرفته هنوز تکمیل نشده‌اند؛ وضعیت ردیف‌به‌ردیف نسخه جدید در FEATURES.md و JSON همراه آن ثبت شده است.
